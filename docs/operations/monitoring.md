# Наблюдаемость

| Сигнал | Где | Назначение |
| --- | --- | --- |
| `/healthz` | backend | процесс жив |
| `/readyz` | backend | готовность, включая доступность БД |
| Заголовки безопасности | `backend/middleware/security_headers.py` | проверяются `tests/test_security_headers.py` |
| Аудит действий | `backend/middleware/audit.py`, `backend/api/audit.py` | кто и что изменил |
| Rate limit | `backend/middleware/rate_limit.py` | защита от перебора |
| Кэш отчётов | Redis/KeyDB (`services/report_cache.py`) | ускорение агрегатов; при недоступности — расчёт напрямую |
| Уведомления | `services/scheduler.py` | напоминания о сроках |

## Минимальные алерты

1. `/readyz` не отвечает 2 минуты (в отличие от `/healthz`, это отказ зависимостей).
2. Доля 5xx выше 1% за 5 минут.
3. Redis недоступен — отчёты замедляются, это деградация, а не отказ.
4. Ошибки GigaChat при включённой сводке.
5. Рост числа 429 (rate limit) — возможен перебор или всплеск нагрузки.

## Чего нет

- Нет `/metrics` и готовых дашбордов: наблюдаемость строится на логах, health-check и аудите.
- Нет распределённой трассировки.
- Нет SLO, зафиксированных числом.
